# RommStar Architecture Specification

## Overview

RommStar is a LaunchBox plugin serving as a state-driven client for Romm servers. It manages metadata synchronization, background multi-profile asset downloading, and on-demand game installation.

## Technical Stack

- **Target Environment:** Visual Studio, WPF
- **UI Framework:** iNKORE (WinUI 3 style controls, Card, ProgressBar, InfoBar)
- **Architecture Pattern:** MVVM (via CommunityToolkit.Mvvm), No Code-Behind in Views.
- **Dependency Injection:** Microsoft.Extensions.DependencyInjection
- **Namespace Guidelines:** RommStar.Core is the base namespace

## Core Architecture Design Principles

1. **Stateless HTTP Client:** Use a single global thread-safe `HttpClient`. Do not configure default authorization headers globally. All requests must capture a snapshot of the active server credentials (`RommServerConfig`) and build individual `HttpRequestMessage` instances to allow runtime server-swapping without breaking active background transfers.
2. **Sequential Platform Synchronization:** Bulk platform synchronizations must run strictly *one platform at a time* via a background channel loop (`PlatformSyncTask`). If multiple platforms are synced, their UI tracking cards appear instantly as "Queued" and process macro-sequentially.
3. **Parallel On-Demand Bypass:** On-demand game downloads (e.g., clicking Play when an items `IGame.Installed == false`) must completely bypass the sequential bulk platform queue, processing immediately on parallel tasks.
4. **Dual-Profile Media Handling:**
   - **Catalog Profile:** Minimal media downloaded during normal platform sync (e.g., BoxFront, Screenshot).
   - **Install Profile:** Full media set downloaded when a game is actively installed (e.g., Video, Manual, Box3D, Music).

## Core API Contracts & Data Structures

- `RommServerConfig`: BaseUrl, ApiToken, ServerName.
- `PlatformSyncJob`: `ObservableCollection`-friendly item representing an iNKORE card. Tracks Status (Queued, ProcessingMetadata, SyncingFiles, Completed, CompletedWithErrors), TotalItems, ProcessedItems, and ErrorCount.
- `DownloadJob`: Captures execution scope, including target path, job type (Media vs Rom), and an `OnSuccessCallback` delegate to execute post-download tasks like database updates
